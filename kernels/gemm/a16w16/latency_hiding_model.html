Why slicing hides HBM latency

A first-order latency-hiding model for the a16w16 GEMM kernels — generalized across v6 (no slice), v7 (slice N), and v8 (slice M+N). Drag the latency slider to see when each kernel stalls.

The setup

Each loop iteration is a double-buffered software pipeline: while the MFMA units compute one K-buffer, the global loads for the next buffer stream in from HBM. The kernel stays at peak throughput only if the compute is long enough to cover that load latency.

Fixed quantities for the 256×256×64 tile (per wave, 4 warps):

C  = 2048 cyc   # MFMA compute per buffer (512 MFMA ÷ 4 warps × 16 cyc)
N  = 16 loads  # buffer_loads to fill one buffer (8 for A + 8 for B)
t  = 64 cyc    # to push one buffer_load through the memory pipe
L  = ? cyc    # HBM round-trip latency (~1000 idle; grows with K & contention)

The model

A kernel is described by how finely it slices its two inputs: s_A row-blocks of A and s_B col-blocks of B, giving R = s_A·s_B compute regions. The pipeline can start a region as soon as its A-block and B-block have landed — so what matters is not the whole buffer, but the loads needed for the first region:

N_first = 8/s_A + 8/s_B  # loads before the first MFMA can fire

stall(L) = max(0,  L + N_first·t − C )       # idle cycles per buffer
L*     = C − N_first·t                           # latency the kernel tolerates before stalling

Slicing shrinks N_first, which raises the latency tolerance L*. Crucially, N_first = 8/s_A + 8/s_B only drops the term you actually slice:

kernel(s_A, s_B)regions Rregion computeN_firstL* toleranceworst single block
v6 · no slice(1, 1)120481610248  (A)
v7 · slice N (B)(1, 2)210241212808  (A un-sliced)
v8 · slice M+N(2, 2)4512815364

Why v7 is imbalanced: it halves B (8→4) but leaves A monolithic (8), so N_first = 8 + 4 = 12 — only halfway to v8's 8. Both regions still wait on the full A load, which stays on the critical path. Only slicing both inputs cuts both terms.

Interactive: efficiency vs. latency

MFMA efficiency = C / (C + stall). Each kernel runs flat-out until L crosses its threshold L* (the kink), then falls as 1 / (1 + (L−L*)/C). v6 tips first (L*=1024), v8 last (L*=1536). As K grows the working set goes cold and the effective L climbs — which is exactly the order in which the kernels collapse in the measured data below.

The two axes of slicing

1 · Compute granularity (regions R)

Finer regions let the MFMA pipe start sooner and follow the load front closely, shrinking the start-up bubble. v6→v7→v8 = 1→2→4 regions.

2 · Load balance (worst input block)

The largest single un-sliced input is a serial dependency every region waits on. v7 fixes only B, so its A-block (8 loads) stays as big as v6's — that's the imbalance.

v8 wins by improving both axes; v7 improves only the compute axis; v6 neither. Symmetric slicing is what drives N_first = 8/s_A + 8/s_B down on both terms at once.

When do you need slicing?

  • Compute the threshold L* = C − N_first·t. For an un-sliced kernel that's C − N·t (here 1024).
  • Slice if your effective L > L*. Effective L grows with the working set (K), cache coldness, and how many CUs hammer HBM at once. If a buffer's latency clears L*, the un-sliced kernel stalls every iteration — slice to raise L*.
  • Slice symmetrically. N_first = 8/s_A + 8/s_B drops fastest when you raise both s_A and s_B. Slicing one side (v7) leaves the other input's full load on the critical path.
  • Diminishing returns + overhead. The first split helps most (16→8); further splitting adds region/barrier overhead. At very large K both v7 and v8 clear the latency bar, and v8's extra per-region barriers let v7 edge ahead (the measured K=32768 crossover).
  • Bonus the model omits: slicing also spreads the loads out (less bursty), which lowers the effective L itself under contention — so the real gap is wider than this single-L model predicts.

Limitations

  • First-order: a single scalar L and a fixed per-load t≈64; both are really distributions that inflate under contention.
  • It models the start-up dependency (N_first) that gates each buffer; it does not model per-region steady-state throughput, LDS-read (lgkmcnt) latency, or bandwidth saturation.
  • It omits the second-order region/barrier overhead that grows with slicing — the reason v7 overtakes v8 at the largest K.
  • Numbers are for the 256×256×64 fp16 tile with 4 warps; the shape of the model (N_first = loadsA/s_A + loadsB/s_B) generalizes, the constants do not.
